# RFC 9068: JSON Web Token (JWT) Profile for OAuth 2.0 Access Tokens

Clauses of [RFC 9068](https://www.rfc-editor.org/rfc/rfc9068) that pulsar,
as an authorization server issuing JWT access tokens, must or should meet.

- REQ-AT-1 (§2.1): "JWT access tokens MUST be signed. [...] JWT access
  tokens MUST NOT use "none" as the signing algorithm."
- REQ-AT-2 (§2.1): "JWT access tokens MUST include this media type in the
  "typ" header parameter to explicitly declare that the JWT represents an
  access token complying with this profile. Per the definition of "typ" in
  Section 4.1.9 of [RFC7515], it is RECOMMENDED that the "application/"
  prefix be omitted. Therefore, the "typ" value used SHOULD be "at+jwt"."
- REQ-AT-3 (§2.2): "iss REQUIRED [...] exp REQUIRED [...] aud REQUIRED
  [...] sub REQUIRED [...] client_id REQUIRED [...] iat REQUIRED [...] jti
  REQUIRED"
- REQ-AT-4 (§2.2.3): "If an authorization request includes a scope
  parameter, the corresponding issued JWT access token SHOULD include a
  "scope" claim as defined in Section 4.2 of [RFC8693]."
- REQ-AT-5 (§3): "If the request does not include a "resource" parameter,
  the authorization server MUST use a default resource indicator in the
  "aud" claim."

  pulsar does not support the `resource` parameter, so every access token's
  `aud` is the default: the issuer.
