# RFC 9068: JSON Web Token (JWT) Profile for OAuth 2.0 Access Tokens

Clauses of [RFC 9068](https://www.rfc-editor.org/rfc/rfc9068) that pulsar,
as an authorization server issuing JWT access tokens, must or should meet.

- REQ-AT-1 (§2.1): "JWT access tokens MUST be signed. [...] JWT access
  tokens MUST NOT use "none" as the signing algorithm."
- REQ-AT-2 (§2.1): "JWT access tokens MUST include this media type in the
  "typ" header parameter to explicitly declare that the JWT represents an
  access token complying with this profile. Per the definition of "typ" in
  Section 4.1.9 of [RFC7515], it is RECOMMENDED that the "application/"
  prefix be omitted. Therefore, the "typ" value used SHOULD be "at+jwt"."
- REQ-AT-3 (§2.2): "iss REQUIRED [...] exp REQUIRED [...] aud REQUIRED
  [...] sub REQUIRED [...] client_id REQUIRED [...] iat REQUIRED [...] jti
  REQUIRED"
- REQ-AT-4 (§2.2.3): "If an authorization request includes a scope
  parameter, the corresponding issued JWT access token SHOULD include a
  "scope" claim as defined in Section 4.2 of [RFC8693]."
- REQ-AT-5 (§3): "If the request does not include a "resource" parameter,
  the authorization server MUST use a default resource indicator in the
  "aud" claim."

  pulsar does not support the `resource` parameter, so every access token's
  `aud` is the default: the issuer.

## Validation at UserInfo (§4)

pulsar validates the access tokens it issued, at its own UserInfo
endpoint, as a resource server must.

- REQ-AT-6 (§4): "The resource server MUST verify that the "typ" header
  value is "at+jwt" or "application/at+jwt" and reject tokens carrying any
  other value."

  The value is compared without regard to case, as RFC 7515 §4.1.9 says
  media type values are.

- REQ-AT-7 (§4): "The issuer identifier for the authorization server
  (which is typically obtained during discovery) MUST exactly match the
  value of the "iss" claim."
- REQ-AT-8 (§4): "The JWT access token MUST be rejected if "aud" does not
  contain a resource indicator of the current resource server as a valid
  audience."

  UserInfo's resource indicator is the issuer, the default audience
  (REQ-AT-5).

- REQ-AT-9 (§4): "The resource server MUST validate the signature of all
  incoming JWT access tokens according to [RFC7515] using the algorithm
  specified in the JWT "alg" Header Parameter. The resource server MUST
  reject any JWT in which the value of "alg" is "none". The resource server
  MUST use the keys provided by the authorization server."

  Only RS256 is accepted, with the key of the JWK Set that the `kid` names.

- REQ-AT-10 (§4): "The current time MUST be before the time represented by
  the "exp" claim."

  pulsar allows no leeway: it validates against its own clock.

- REQ-AT-11 (§4): "In particular, in case of any failure in the validation
  checks listed above, the authorization server response MUST include the
  error code "invalid_token"."
