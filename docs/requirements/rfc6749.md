# RFC 6749: The OAuth 2.0 Authorization Framework

Clauses of [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749) that pulsar,
as an authorization server, must or should meet.

## Client password (§2.3.1)

- REQ-OAUTH-3 (§2.3.1): "The authorization server MUST support the HTTP
  Basic authentication scheme for authenticating clients that were issued
  a client password."

  The client identifier and password are each form-encoded before Basic
  encoding, as §2.3.1 says, and are decoded the same way. A Client that
  registers `client_secret_basic` may authenticate by it alone.

## Authorization endpoint (§3.1)

- REQ-OAUTH-4 (§3.1): "The authorization server MUST ignore unrecognized
  request parameters."
- REQ-OAUTH-5 (§3.1): "Request and response parameters MUST NOT be included
  more than once."

  A repeated `client_id` or `redirect_uri` gets the error page, since
  neither can be trusted to redirect to; any other repeated parameter
  pulsar reads gets `invalid_request`, at either endpoint.

- REQ-OAUTH-6 (§3.1): "Parameters sent without a value MUST be treated as
  if they were omitted from the request."

## Redirection endpoint (§3.1.2)

- REQ-OAUTH-1 (§3.1.2): "The redirection endpoint URI MUST be an absolute
  URI as defined by [RFC3986] Section 4.3. ... The endpoint URI MUST NOT
  include a fragment component."

- REQ-OAUTH-2 (§3.1.2.2): "The authorization server SHOULD require all
  clients to register their redirection endpoint prior to utilizing the
  authorization endpoint."

## Authorization response (§4.1.2)

- REQ-OAUTH-7 (§4.1.2, `code`): "The authorization code MUST expire shortly
  after it is issued to mitigate the risk of leaks. A maximum authorization
  code lifetime of 10 minutes is RECOMMENDED."

  A code expires 60 seconds after it is issued.

- REQ-OAUTH-8 (§4.1.2, `code`): "The authorization code is bound to the
  client identifier and redirection URI."
- REQ-OAUTH-9 (§4.1.2, `state`): "REQUIRED if the "state" parameter was
  present in the client authorization request. The exact value received
  from the client."

  pulsar returns `state` in error responses too, as §4.1.2.1 also
  requires.

- REQ-OAUTH-10 (§4.1.2.1): "If the request fails due to a missing, invalid,
  or mismatching redirection URI, or if the client identifier is missing or
  invalid, the authorization server SHOULD inform the resource owner of the
  error and MUST NOT automatically redirect the user-agent to the invalid
  redirection URI."

## Access token request (§4.1.3)

- REQ-OAUTH-11 (§4.1.3): "ensure that the authorization code was issued to
  the authenticated confidential client, or if the client is public, ensure
  that the code was issued to "client_id" in the request"
- REQ-OAUTH-12 (§4.1.3): "ensure that the "redirect_uri" parameter is
  present if the "redirect_uri" parameter was included in the initial
  authorization request as described in Section 4.1.1, and if included
  ensure that their values are identical."

## Token responses (§5)

- REQ-OAUTH-13 (§5.1): "The authorization server MUST include the HTTP
  "Cache-Control" response header field [RFC2616] with a value of
  "no-store" in any response containing tokens, credentials, or other
  sensitive information, as well as the "Pragma" response header field
  [RFC2616] with a value of "no-cache"."

  pulsar sends both on every token endpoint response, errors included.

- REQ-OAUTH-14 (§5.2, `invalid_client`): "If the client attempted to
  authenticate via the "Authorization" request header field, the
  authorization server MUST respond with an HTTP 401 (Unauthorized) status
  code and include the "WWW-Authenticate" response header field matching
  the authentication scheme used by the client."

  pulsar answers every `invalid_client` this way, naming the Basic scheme
  even to a Client that sent no `Authorization` header, which §5.2 allows.

- REQ-OAUTH-15 (§5.2): "The authorization server responds with an HTTP 400
  (Bad Request) status code (unless specified otherwise) and includes the
  following parameters with the response: error REQUIRED."

## Security considerations (§10)

- REQ-OAUTH-16 (§10.5): "Authorization codes MUST be short lived and
  single-use."
