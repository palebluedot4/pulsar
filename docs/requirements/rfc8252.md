# RFC 8252: OAuth 2.0 for Native Apps

Clauses of [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252) that pulsar,
as an authorization server, must or should meet.

## Loopback interface redirection (§7.3)

- REQ-NATIVE-1 (§7.3): "The authorization server MUST allow any port to be
  specified at the time of the request for loopback IP redirect URIs, to
  accommodate clients that obtain an available ephemeral port from the
  operating system at the time of the request."

  A loopback IP redirect URI is one §7.3 describes: "<http://127.0.0.1:{port}/{path}>"
  for IPv4, and "http://[::1]:{port}/{path}" for IPv6. A Client registers
  it with or without a port; a request may name it with any port from 1 to
  65535, or none, and must otherwise equal it exactly, as every other
  redirect URI must (REQ-CORE-5). The response goes to the URI the request
  names, and the code is redeemed for that URI alone (REQ-OAUTH-12).

  A URI whose host is `localhost` gets no such exception: §8.3 says that
  "the use of localhost is NOT RECOMMENDED", because a loopback IP literal
  "avoids inadvertently listening on network interfaces other than the
  loopback interface" and "is also less susceptible to client-side
  firewalls and misconfigured host name resolution on the user's device."
