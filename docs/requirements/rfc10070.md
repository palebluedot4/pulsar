# RFC 10070: Updates to OAuth 2.0 JWT Client Authentication and Assertion-Based Authorization Grants

Clauses of [RFC 10070](https://www.rfc-editor.org/rfc/rfc10070) that
pulsar, as an authorization server that authenticates Clients registered
for `private_key_jwt`, must or should meet. It updates RFC 7523 §3
(REQ-JWTAUTH-3); its updates to the authorization grants, SAML assertions
and Pushed Authorization Requests concern nothing pulsar offers.

- REQ-ASSERTAUD-1 (§4, RFC 7523 §3 item 3 as replaced, case B): "For client
  authentication, the "aud" (audience) claim value MUST use the issuer
  identifier [RFC8414] of the authorization server as its sole value.
  [...] this includes that the token endpoint URL of the authorization
  server MUST NOT be used as an audience value. The authorization server
  MUST reject any JWT that does not contain its issuer identifier as its
  sole audience value."

  The sole value may be a string or an array of one: RFC 10070 does not
  restrict the type ([ADR 0006](../adr/0006-client-assertions-name-the-issuer-as-sole-audience.md)).

- REQ-ASSERTAUD-2 (§4): "In the absence of an application profile
  specifying otherwise, applications MUST compare the audience values
  using the Simple String Comparison method defined in Section 6.2.1 of
  [RFC3986]."

§4 also says Client authentication JWTs "SHOULD be explicitly typed" with
`typ` `client-authentication+jwt`, a requirement of the Client, and that
"it is NOT RECOMMENDED for servers to reject JWTs that do not have explicit
types". pulsar does not read `typ`.
