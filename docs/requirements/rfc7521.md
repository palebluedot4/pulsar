# RFC 7521: Assertion Framework for OAuth 2.0 Client Authentication

Clauses of [RFC 7521](https://www.rfc-editor.org/rfc/rfc7521) that pulsar,
as an authorization server that authenticates Clients by JWT assertions
(RFC 7523), must or should meet. Assertions as authorization grants (§4.1)
are not offered.

- REQ-ASSERT-1 (§4.2, `client_id`): "If present, the value of the
  "client_id" parameter MUST identify the same client as is identified by
  the client assertion."

  A `client_id` that names another Client gets `invalid_client`, as
  REQ-ASSERT-2 says of an invalid assertion.

- REQ-ASSERT-2 (§4.2.1): "If an assertion is invalid for any reason or if
  more than one client authentication mechanism is used, the authorization
  server constructs an error response as defined in OAuth 2.0 [RFC6749].
  The value of the "error" parameter MUST be the "invalid_client" error
  code."

  A request that carries `client_assertion` or `client_assertion_type`
  together with an `Authorization` header or a `client_secret` gets
  `invalid_client`. Two methods without an assertion get
  `invalid_request`, as RFC 6749 §5.2 defines it (REQ-OAUTH-24).
