# RFC 8725: JSON Web Token Best Current Practices

Clauses of [RFC 8725](https://www.rfc-editor.org/rfc/rfc8725) that pulsar,
as an application that verifies the JWTs Clients sign to authenticate
(`private_key_jwt`), must or should meet.

- REQ-JWTBCP-1 (§3.1): "Moreover, each key MUST be used with exactly one
  algorithm, and this MUST be checked when the cryptographic operation is
  performed."

  The clause is addressed to libraries; pulsar meets it itself. The
  registry refuses a Client's key that does not name its algorithm in
  `alg`, and an assertion verifies only with a key whose `alg` is the
  assertion's.

- REQ-JWTBCP-2 (§3.2): "Therefore, applications MUST only allow the use of
  cryptographically current algorithms that meet the security requirements
  of the application."

  The allow-list is RS256, PS256 and ES256. It holds no HMAC algorithm,
  since `client_secret_jwt` is not offered, and never `none`. Discovery's
  `token_endpoint_auth_signing_alg_values_supported` is the same list.

- REQ-JWTBCP-3 (§3.8): "When a JWT contains an "iss" (issuer) claim, the
  application MUST validate that the cryptographic keys used for the
  cryptographic operations in the JWT belong to the issuer. If they do
  not, the application MUST reject the JWT."

  An assertion is verified only with the keys the registry holds for the
  Client it names.
