# RFC 7591: OAuth 2.0 Dynamic Client Registration Protocol

Clauses of [RFC 7591](https://www.rfc-editor.org/rfc/rfc7591) on the Client
metadata pulsar's registry holds. pulsar does not offer Dynamic Client
Registration: Clients are read from a static file
([ADR 0001](../adr/0001-clients-and-end-users-from-a-static-file.md)), whose
members carry the names and forms of RFC 7591 §2. The evidence is in
[the research](../research/client-credentials.md#rfc-7591-metadata).

## Client metadata (§2)

- REQ-CLIENTMETA-1 (§2, `grant_types`): "If omitted, the default behavior is
  that the client will use only the "authorization_code" Grant Type."

  Departure: a Client that leaves `grant_types` out uses
  `authorization_code` and `refresh_token`, the grants every Client used
  before the registry had `grant_types`, so that a registry written then
  keeps working. A Client lists `client_credentials` alone, or
  `authorization_code` and `refresh_token` both; pulsar refuses to start
  on any other list, since it has no Client of the code flow without
  refresh tokens.

- REQ-CLIENTMETA-2 (§2, `scope`): "String containing a space-separated list
  of scope values (as described in Section 3.3 of OAuth 2.0 [RFC6749])
  that the client can use when requesting access tokens."

  Only a machine Client lists `scope`, at least one value, each once,
  separated by single spaces, and each a scope of a Resource Server it
  lists in `resource_servers`. With no End-User to consent, the registry
  is what authorizes them. A Client of the code flow gets its scopes from
  the End-User's consent, so pulsar refuses to start on one that lists
  `scope`, which would do nothing.

## Grant types registered together (§5)

- REQ-CLIENTMETA-3 (§5): "For security reasons, an authorization server
  could require that different scopes be used for these different use
  cases, and, as a consequence, it MAY disallow these two grant types from
  being registered together by the same client."

  pulsar does: a Client that lists `client_credentials` lists no other
  grant type, so it acts either for End-Users or for itself, and the `sub`
  of its access tokens says which (REQ-BCP-17). Keycloak, Ory Hydra and
  Auth0 allow both on one Client.
